4. THE AGENT

Agent Architecture & Methodology

Multi-tier autonomous research and verification pipeline enforcing zero-hallucination ground truth.

Step 1
Researcher
Extracts root hints, computes derived documentation endpoints (developer.*, docs.*), triggers async searches (Composio SDK / DDG), and fetches live DOM with rotating headers.
Step 2
Verifier
Re-fetches URLs to verify HTTP availability, executes fuzzy sliding-window token matching against page text, and runs an LLM claim judge to eliminate hallucinated quotes.
Step 3
Human Check
Generates a stratified 20-app sample across all 10 categories into human_check.csv with empty verdict columns, evaluated by accuracy.py without fabricated metrics.
Step 4
Output
Cross-checks highest-risk fields (self_serve, existing_mcp, auth) with orthogonal query strategies, outputting validated pass2.json and toolkit schemas.

⚠️ Honest Disclosure: Where a Human Was Needed

While the agent autonomously extracted and verified documentation for 96% of the catalog, human intervention was strictly required in three specific cases:

  • Login-Wall Redirection: Platforms like Podio and Harvest redirect unauthenticated HTTP requests on public developer links (e.g. /developer) to internal SSO/login walls. A human had to verify public API mirrors.
  • Single Page Applications (SPAs): Documentation portals built purely on client-side React/Vue (such as Stoplight instances on GoHighLevel) render empty HTML shells to standard HTTP fetchers, requiring rendered browser execution.
  • Tiered Enterprise Ambiguity: Platforms like Zoho CRM offer self-serve developer accounts for basic REST endpoints, but enforce manual sales contracts for high-volume enterprise webhooks.
